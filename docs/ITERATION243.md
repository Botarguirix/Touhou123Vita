# Iteración 2.143: localizado productor condicional de la acción 418

La búsqueda en el PE fijado encuentra una ruta de movimiento común en `0x4b0ac2` que, tras guards de estado y la consulta de disponibilidad `0x489610(0x1a2)`, empuja la acción 418 en `0x4b0b04` y llama el setter virtual de la instancia en `0x4b0b29`. El layout `SokuLib/Player.hpp` identifica `KeyInput` actual en `+0x754` y `bufferedKeyInput` en `+0x774`: la rama permite eje horizontal actual o buffered con signo compatible con `facing`, y exige eje vertical actual `+0x758 == 0`, acción actual cero y disponibilidad del recurso. La vertical buffered `+0x778` no forma parte de este guard. Antes del setter escribe `0.0` en `Player+0x12c`; luego salta a `0x46cac0`, que limpia los campos del input buffered y contadores asociados.

Se añadió `tools/x86_suika_418_producer_probe.py` para exportar instrucciones y guards con SHA del PE. Su modo dinámico ejecuta el bloque original `0x4b0ac2` y el limpiador original `0x46cac0`, aislando solamente grounded, move-lock y setAction: ocho casos confirman entradas actual/buffered válidas, rechazos por facing/eje vertical/suelo/move-lock y que el buffer se limpia tras setAction. Un caso clave acepta horizontal actual hacia delante aunque `+0x778` sea cero. Evidencia: [x86-suika-418-producer.json](../artifacts/x86-suika-418-producer.json). Tres pruebas focalizadas de productor, guards y timeline pasan.

Límite: el bloque de decisión y limpiador sí se ejecutan desde el PE, pero con stack interior preparado y servicios de suelo/move-lock/setAction controlados; no se ejecuta el loop completo ni KeyManager/replay, y falta verificar el setter real de Suika en esta ruta. El harness de timeline sigue usando suelo controlado 500 y Y fija; no se afirma salto natural. Sin cambio de runtime Vita ni VPK.
