# Iteración 2.90: tipo de offsets PAT y slot de dibujo compartido

La ruta original confirma que `0x466670` lee palabras con signo de `+4/+6` y las copia al componente gráfico `+0xf0/+0xf4`. El parser C y el extractor Python conservan por ello `tx/ty` como `int16`; las dimensiones siguen sin signo. Sin embargo, esos campos no bastan para colocar el quad desde la posición mundial del prototipo: el PE configura geometría adicional mediante `0x406c60` y usa después su origen local durante el dibujo. El PAT idle de Reimu da `tx=0, ty=0, ox=90, oy=234`; una prueba visual mostró que proyectar directamente `tx/ty` corta los sprites bajo el HUD. Se retiró esa fórmula incompleta y se conservó el anclaje previo con `ox/oy` como aproximación pendiente de reconstrucción del quad.

El probe SHA-pinned [x86_sprite_vtable_probe.py](../tools/x86_sprite_vtable_probe.py) verificó que el slot 11 de Reimu (`0x85bf4c`), del objeto base (`0x85f1d4`) y de Suwako 808 (`0x85f22c`) apunta al mismo renderer `0x438d20`. Esto prueba el callback compartido; todavía hay que confirmar cómo cada clase configura el origen y la geometría de su quad. El reporte está en [sprite-render-vtable-contract.json](../artifacts/kernel/sprite-render-vtable-contract.json).

Tras retirar la fórmula incompleta, VitaSDK compiló y Vita3K SDL pasó 600 cuadros/schema46 con regresión general, cámara, BG33 y scroll BG36–BG38 aprobados. Python pasó 110/110; el test focalizado volvió a pasar 10/10 tras corregir la expectativa del renderer. Captura fresca: [fight.bmp](../artifacts/screenshots/fight.bmp). Una fixture C para `tx=-2, ty=3` está añadida, pero no se ejecutó como prueba host porque no hay compilador C/CMake nativo en PATH.
