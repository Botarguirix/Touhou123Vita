# Iteración 2.04: factory original de Remilia 801 bajo Unicorn

El harness de factory x86 se parametrizó por personaje/acción y se amplió el espacio del fixture PAT para secuencias de 20 frames, conservando los valores por defecto de Suwako 808. La regresión original de Suwako vuelve a completar factory y ocho updates con action 808/seq.1.

Con Remilia action 801, el factory original `0x784020` crea el objeto (vtable `0x85f22c`) y ejecuta su initializer; el resultado es action 801, seq.1, posición controlada `(300,400)`, color/alpha inicial blancos y `+0x34c=1`. El harness también ejecuta el selector de pose y sincronizador original `0x465e10`: PAT seq.0 publica una attack box y seq.1 ninguna, con cero hurtboxes en ambas.

El update original `0x7876d0` avanza tres ticks en seq.1; en el cuarto intenta continuar por un servicio de Windows y falla con una lectura indirecta a la dirección inválida `0x8a896c0d` (`EIP=0x4818c2`). El slot IAT `0x857190` que se llama en la traza corresponde a `KERNEL32!TlsGetValue`; también aparece la búsqueda de `KERNEL32.DLL!DecodePointer` (`GetModuleHandleA`/`GetProcAddress`). Unicorn no ejecuta el loader de Windows ni resuelve esas importaciones del PE, así que la excepción ocurre antes de evaluar el siguiente estado del ataque. Por eso no se afirma ciclo de vida, secuencia ofensiva natural ni daño. El registro de acceso inválido y el trace están en `artifacts/kernel/remilia-object801-factory.json` (ignorado). `pytest` no está instalado en el Python local; la regresión funcional del harness Suwako se ejecutó directamente y pasó.
