# Iteración 2.13: cadencia de dispersión de Remilia 801

Se identificó el origen de las factories adicionales observadas en Iteración 2.12. La tabla original despacha action `0x321` a `0x7879da`; para seq.0 salta a `0x7879f1`. Esa rama omite la dispersión cuando `object+0x190 == 5`; en el modo activo pone divisor 3, divide el contador `object+0x144`, y continúa solo con residuo cero. Entonces obtiene el callback de creación desde `object.vtable+0x44` y solicita otro action `0x321` usando las coordenadas actuales del objeto.

La traza administrada del hijo original registra 19 solicitudes en 55 ticks. Todas salen desde el mismo objeto inicial `0x1100040`, en el sitio de retorno `0x787a85`, con poses `[0,3,6,9,12,15,18,1,4,7,10,13,16,19,2,5,8,11,14]`. Cada factory retorna un objeto válido action 801. El manager llega a `+0x34c=0` para el padre y lo desenlaza; seis instancias 801 continúan en la lista. Esto explica por qué las instancias aparecen, pero aún no caracteriza todas sus diferencias de movimiento/impacto ni cómo la fase de parejas las consume.

Se agregó al análisis estático una comprobación de la tabla de dispatch, guard de modo, divisor/cadencia y callsite virtual; regresión dinámica para el número, origen y poses de las solicitudes. La matriz hit-vs-hurt sigue dando contacto a distancias X 0/40/60 y ninguno desde 70. No se ejecuta aún `0x47cb70/0x47ce20` dentro de una actualización de pelea, ni se mide HP/guardia/hitstop.
